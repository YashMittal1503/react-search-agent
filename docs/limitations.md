# Limitations (read before using)

Scout runs entirely on **free** model and search tiers. Numbers were checked in November 2026 and change often.

| Area | What to expect | What the code does about it |
|---|---|---|
| **Rate limits** | Groq free: 30 RPM, 1K RPD, **8K tokens/min**, 200K tokens/day *per model*. OpenRouter `:free`: 20 RPM, **50 requests/day**. Gemini/Mistral/NVIDIA: per-project caps, often 429 or 503 at peak hours. | `llm-key-pool`: 5 providers × several keys, per-(key, model) cooldowns from `Retry-After`, overloaded models skipped after one try, requests too big for a model's limit skipped without a call, daily limits held until the provider's reset, fallback tiers in `models.yaml`. Free tiers still run out at peak: limits shrink, they never disappear. |
| **Keys don't multiply quota** | Several keys from one account share that account's limits. | More *providers* is what adds headroom. Set `shared_quota: true` (or `<PREFIX>_SHARED_QUOTA=true`) for such a provider so one 429 cools all its keys. Cerebras is left out: it has no lasting free tier, only a $5 trial. |
| **Small TPM vs. web pages** | A deep-research run makes 10–25 LLM calls and reads 50–150K tokens. Expect a handful of deep runs per hour. | Pages never go to the model raw: BM25-picked passages (~800 tokens per page). Old tool outputs are cleared from the agent's context. The orchestrator runs on high-TPM providers, and synthesis runs on 1M-context Gemini first. |
| **Tool-calling quality** | Open models sometimes call tools that don't exist, loop, or stop early. | Malformed calls fail over to the next model. Model-call and search caps, timeouts, and a writer step that always runs on whatever was gathered. |
| **Answer quality** | Below GPT/Claude-class models, especially for long synthesis. | Every claim cites an id. The citation guard drops ids that don't exist, so a citation always points to a real fetched/search URL. Faithfulness (claim matches source) is measured by the eval judge but not guaranteed. |
| **Latency** | Quick: ~5–20 s. Deep: 1–4 min. Fallbacks add variance. | Live research timeline, streamed tokens. |
| **Search** | Without keys, search uses DuckDuckGo and other ddgs engines, which throttle bursts and sometimes return nothing. Tavily (1K/month) or Exa ($10/month credit) improve results a lot. | Provider fallback chain, multi-engine rotation, `site:` retry, caching, per-run search cap. |
| **Scraping** | ~86% of a mixed 35-URL benchmark returns usable text without a headless browser. Paywalls, logins and hard bot walls (NYT, Instagram) fail. | Waterfall of site APIs, HTTP, optional browser, Jina Reader and Wayback, with per-domain learning. **No CAPTCHA solving, bot-detection evasion or paywall bypass**: when a site refuses, the agent uses another source. |
| **Privacy** | Gemini's free tier may use prompts to improve Google products. | Don't type personal data. No user PII is stored (anonymous browser id only). |
| **Model churn** | Free model lists change weekly (models get retired or go paid). | `python -m app.llm.llm_pool.healthcheck` shows which models are alive; tiers are YAML. |
| **Evals** | The LLM judge is a free model, so rubric/faithfulness scores are noisy. Live items (weather, news) are checked on behaviour and freshness, not fixed answers. | Judge from a different model family than the agent; cached verdicts; deterministic fixture pages for robustness. |
| **Hosting** | The backend isn't deployed yet (no free host fits a headless browser comfortably). | Dockerfile is ready for Cloud Run / Render / a VM; frontend is ready for Vercel. |
